# Order Operations Analytics

An end-to-end data analytics project on e-commerce order operations: **clean messy data in Python (Pandas) → analyse it with SQL → present it in an interactive dashboard.**

Built to apply what I learned in the **Imarticus Learning Data Analytics internship** (Python, SQL and dashboards) to an operations problem.

## The business question

An Indian e-commerce business ships ~6,000 orders a year through five courier partners. Management wants to know:

1. Are we delivering on time? Where and when do we miss the promised date (SLA)?
2. Which courier partners perform best and worst?
3. Why do customers return orders, and which categories and payment modes are riskiest?
4. Does late delivery actually hurt customer ratings?

## Key findings

| # | Finding | Number |
|---|---|---|
| 1 | Festive season (Oct–Nov) overloads the warehouse | Late deliveries jump from **15.5% → 61.3%** |
| 2 | Courier choice matters | BlueDart **12.1%** late vs India Post **63.2%** late |
| 3 | Late delivery hurts ratings | **4.19★** on time vs **3.07★** late |
| 4 | Cash on Delivery is risky | COD cancelled **7.7%** vs prepaid **2.9%** |
| 5 | Fashion drives returns | **20.4%** return rate; half are size/fit issues |

Full write-up with recommendations: [`outputs/insights.md`](outputs/insights.md)

## Tools

| Step | Tool | What it does |
|---|---|---|
| Data cleaning | Python, Pandas | Removes duplicates, fixes 3 date formats, standardises labels, converts prices, drops invalid rows, adds derived columns |
| Analysis | SQL (SQLite) | 12 queries using `GROUP BY`, `CASE`, CTEs and window functions (`RANK`, `ROW_NUMBER`, `SUM() OVER`) |
| Dashboard | HTML, CSS, JavaScript, Chart.js | Interactive filters (region, category, courier, payment, month), KPIs, 7 charts and a city table |
| Hosting | GitHub Pages | Free static hosting from the `docs/` folder |

## Data cleaning summary

Raw file: **6,150 rows** → clean file: **5,941 rows** (209 removed). Every step is logged in [`outputs/cleaning_report.md`](outputs/cleaning_report.md).

| Problem in the raw data | Fix |
|---|---|
| 150 exact duplicate rows | `drop_duplicates()` |
| Dates in 3 formats (`2025-03-14`, `14/03/2025`, `14-Mar-2025`) | Parsed each format, merged into one date column |
| City names like `bangalore`, `BENGALURU`, `Bombay`, `Calcutta` | Mapped to one standard name |
| Payment labels like `cod`, `Cash on Delivery`, `C.O.D` | Mapped to 5 standard modes |
| Prices stored as text (`₹1,299.00`) | Removed `₹` and commas, converted to number |
| 336 blank regions | Filled from the city |
| Missing city, quantity ≤ 0, delivery date before order date | Rows dropped (cannot be fixed reliably) |
| Missing customer ratings | **Kept blank** on purpose: filling them would bias the average |

New columns added: `net_revenue`, `days_to_ship`, `days_to_deliver`, `sla_days`, `sla_breached`, `is_returned`, `festive_season`, `order_month`, `city_tier`.

## Run it yourself

```bash
pip install -r requirements.txt
python run_all.py
```

Then open `docs/index.html` in a browser. The SQLite database is written to `data/orders.db`; you can open it in [DB Browser for SQLite](https://sqlitebrowser.org/) and run the queries from `sql/analysis_queries.sql` yourself.

## Deploy the dashboard (GitHub Pages)

1. Push this folder to a new public GitHub repository.
2. In the repo, go to **Settings → Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**, branch **main**, folder **/docs**, then **Save**.
4. After a minute the site is live at `https://<your-username>.github.io/<repo-name>/`. Paste that link at the top of this README.

## About the data

The dataset is **synthetic**: `01_generate_data.py` creates it with a fixed random seed so results are reproducible. It is modelled on a real order export (Indian cities, real courier names, festive-season peaks, COD behaviour) and deliberately includes the errors found in real exports so the cleaning step is meaningful. The numbers do not describe any real company.
